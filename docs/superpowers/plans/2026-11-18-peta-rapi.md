# Peta Rapi Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use subagent-driven development (recommended) or inline execution to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ganti tata letak d3-force yang acak dengan pohon kiri-ke-kanan yang deterministik.

**Architecture:** Fungsi murni `treeLayout(ids)` menghitung pusat tiap kartu dari `D` (urutan `derive()`) dan ukuran `boxOf`. `rebuild()` memakai hasilnya sebagai target; posisi bergerak ke target lewat tween `d3.timer` (langsung bila `reduceMotion`). Seret = geser sementara, tombol Rapikan dan setiap `refresh()` mengembalikan target.

**Tech Stack:** index.html tunggal, D3 v7 (zoom, drag, timer, ease), pytest + Playwright.

**Spec:** `docs/superpowers/specs/2026-11-18-peta-rapi-design.md`

## Global Constraints
- Satu file `index.html`, tanpa build step; semua tes lama (29) tetap hijau.
- Kartu tidak boleh beririsan; anak selalu di kanan induknya; urutan anak = urutan `derive()` (kategori dulu, lalu materi, abjad).
- Kategori utama ditumpuk vertikal di kolom pertama; warna dan semantic zoom tidak berubah.
- Posisi hasil seret tidak disimpan. `prefers-reduced-motion`: tanpa animasi.
- Skema dan data Supabase tidak berubah.

## Review Focus
- Tanpa kategori sama sekali (`#empty` tampil): `treeLayout([])` kembali kosong, `fit` tidak error.
- Satu akar tanpa anak, dan akar dengan ratusan anak: tidak ada irisan, tidak ada NaN.
- Label sangat panjang (lebar kartu beragam antar kolom): kolom memakai kartu terlebar, anak tidak menimpa induk.
- Seret kartu lalu buka/tutup cabang: semua kembali rapi, tidak ada kartu "tertinggal" di tempat lama.
- Hapus kategori atau materi saat sebagian simpul sedang bergerak: tween tidak menulis ke simpul yang sudah hilang.
